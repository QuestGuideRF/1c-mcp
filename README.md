# 1C MCP Server

`1C MCP Server` — проект для интеграции 1С:Предприятия с AI-клиентами через Model Context Protocol (MCP). В репозитории собраны готовое расширение 1С и Python-прокси, который упрощает подключение клиентов, добавляет гибкость транспорта и закрывает вопросы аутентификации.

## ✨ Особенности

- Готовое расширение 1С с HTTP-сервисом MCP для быстрого старта.
- Поддержка MCP-инструментов для работы с данными и метаданными 1С.
- Python-прокси на `FastAPI` для интеграции с MCP-клиентами.
- Поддержка `OAuth2` в прокси и проброса авторизации в 1С backend.
- Варианты запуска локально и через Docker.
- Примеры клиентских настроек в `mcp_client_settings/`.

## 🚀 Быстрый старт

### 1) Установка расширения 1С

- Используйте файл `build/MCP_Сервер.cfe`.
- Опубликуйте HTTP-сервис `mcp_APIBackend`.
- Проверьте, что endpoint базы доступен по ожидаемому URL.

### 2) Запуск Python-прокси (рекомендуется)

```bash
cd src
python -m venv .venv
. .venv/bin/activate
pip install -r py_server/requirements.txt
python -m py_server
```

Зависимости прокси: `fastapi`, `uvicorn`, `httpx`, `pydantic`, `pydantic-settings`, `python-dotenv`, `mcp`.

### 3) Запуск через Docker (опционально)

- Скопируйте `.env.docker.example` в `.env`.
- Заполните `MCP_ONEC_URL`, `MCP_ONEC_USERNAME`, `MCP_ONEC_PASSWORD`.
- Запустите контейнеры командой `docker-compose up -d`.

## ⚙️ Конфигурация

Минимальный набор параметров для прокси:

- `MCP_ONEC_URL` — URL опубликованной базы 1С.
- `MCP_ONEC_USERNAME` — логин пользователя 1С.
- `MCP_ONEC_PASSWORD` — пароль пользователя 1С.
- `MCP_HOST` / `MCP_PORT` — адрес и порт прокси.
- `MCP_AUTH_MODE` — режим авторизации (`none` или `oauth2`).

## 📁 Структура проекта

- `build/` — собранное расширение 1С (`.cfe`).
- `src/` — исходники компонентов проекта.
- `src/py_server/` — MCP-прокси на Python (`FastAPI` + MCP).
- `mcp_client_settings/` — примеры конфигураций для MCP-клиентов.
- `.env.docker.example` — пример переменных окружения для запуска в Docker.

## 🛠 Использование

1. Подключите MCP-клиент к опубликованному endpoint.
2. Если нужен `stdio`-транспорт и централизованная авторизация, подключайте клиента к Python-прокси.
3. Для расширения функциональности добавляйте собственные MCP-инструменты на стороне 1С.
4. Для production-сценариев используйте запуск через Docker и явную конфигурацию окружения.

## 📌 Примечания по эксплуатации

- Предпочтительный путь подключения в реальной среде — через прокси.
- При размещении 1С и Docker на одном хосте обычно используют `host.docker.internal` вместо `localhost`.
- Перед интеграцией с клиентами удобно проверить доступность endpoint обычным HTTP-запросом.
